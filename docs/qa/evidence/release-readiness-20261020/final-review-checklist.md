## Mobile shelf framing hypothesis — source read-only

Inspected only `CameraRig` in `PoolScene.tsx`, `visibleCameraFrame()` in
`camera.ts` and the current component dimensions. No code edits.
`visibleCameraFrame()` subtracts actual marked overlay rectangles, retains
maximal free rectangles, then scores each by
`min(width / preferredAspect, height)` when a subject aspect is supplied.
The Shelf aspect comes from its actual points/direction. Local framing applies
that selected rectangle using a view offset. Thus a tall subject may score
higher in the taller left region beside the right toolbar than in a shallow
full-width strip above it. The algorithm does not separately prefer visual
centering in the canvas. This is a possible explanation for C's430px capture,
not a reproduced defect or proven causal input.

Fresh live replay must record viewport and actual marked-overlay DOM rectangles,
focus and selected run. Distinguish clipping of the selected shelf/stairs/chaises
from the intentionally cropped irrelevant deep basin. Merely forcing the wide
strip may make the object smaller because usable height falls; do not prescribe
that as a fix without an actual subject-visibility comparison.
